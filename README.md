# 小猫修理工 · BOSS 自我介绍助手

一个 Chrome 扩展：在 BOSS直聘 岗位详情页**自动读取岗位描述**，用 AI 生成**贴合该岗位**的定制化自我介绍，一键复制粘贴到打招呼消息里。

界面上有一只（可拖动的）小猫修理工动画，它把粗糙的岗位 JD「打磨」成你的自我介绍。

> 基于 Manifest V3，无后端、无遥测。所有 AI 请求都直接发往**你自己配置的** API，数据不经过任何第三方服务器。

---

## ✨ 功能

- **自动抓取岗位信息**：读取渲染后的 DOM 文本（含岗位标题、描述、任职要求、公司名），三级兜底策略应对 BOSS 改版
- **贴合岗位的自我介绍**：AI 只使用你在设置里填写的**真实经历**作为素材，突出与岗位最相关的部分，绝不编造
- **防思考过程泄漏**：识别推理模型把「思考过程/多版草稿」写进正文的情况，并自动从中提取最终成品
- **小猫修理工动画**：4 组帧动画（待机 / 钻钻钻 / 完工 / 交付），随交互切换；可拖动到任意位置并记忆
- **多服务商支持**：任何 OpenAI 兼容接口（DeepSeek / Kimi / 通义千问 等，内置预设）
- **34 个自动化测试**覆盖核心逻辑

---

## 🤔 为什么能读取「禁止复制」的岗位描述？

BOSS 的「禁止复制」是通过 CSS / 复制事件限制**用户的选择和剪贴板**，
但岗位描述必须渲染成文字你才能看到 —— **这些文字就在页面 DOM 里**。

扩展的 content script 直接读取渲染后的 DOM 文本（不走剪贴板），
这属于「读取你自己浏览器里已显示的页面内容」，**不是抓接口、不是批量爬取**，
是一款个人求职辅助工具。扩展也不会上传页面数据。

## 📦 安装

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车
2. 右上角开启「**开发者模式**」
3. 点「**加载已解压的扩展程序**」，选择本项目文件夹
4. 扩展图标出现在工具栏

> 修改代码后，在 `chrome://extensions/` 点「重新加载」即可生效；**并记得刷新已打开的 BOSS 页面**（否则页面里运行的是旧脚本）。

## ⚙️ 首次配置（必做）

点扩展图标 → 「设置」，或在岗位面板点右上角「设置」：

| 设置项 | 说明 |
|---|---|
| **API Key** | 必填。到 [platform.deepseek.com](https://platform.deepseek.com) 等平台创建 |
| API 地址 / 模型 | 默认 DeepSeek；Kimi、通义千问有一键预设，也可填任意 OpenAI 兼容服务 |
| **姓名** | 必填，用于自我介绍开头 |
| 结尾语 | 默认「有作品集可发，期待您的回复～」 |
| **真实经历素材** | 必填，**每行一条**。⚠️ 这是防编造的关键：生成时模型**只被允许**使用这里的事实 |

填好后点「保存设置」，再点「测试连接」验证。

> 💡 **强烈建议使用非推理模型**（如 `deepseek-chat`）。推理模型容易把思考过程写进正文、也更慢。
> 即使发生了，扩展也会自动清理（见下文「思考过程泄漏」）。

## 🚀 使用

1. 打开任意 BOSS直聘 岗位详情页（`zhipin.com`）
2. 页面右下角出现**小猫修理工**，点击打开面板
3. 面板自动抓取岗位标题与描述；抓不全时可手动补充，或点「重新抓取页面内容」
4. 点「**一键生成自我介绍**」（约 3–15 秒，取决于模型）
5. 点「**给咪师父点赞并复制**」，粘贴到 BOSS 打招呼处

**小猫的交互状态**

| 猫的动作 | 出现时机 |
|---|---|
| 待机 / 热身 | 页面加载后常驻（悬停有气泡文案） |
| 钻钻钻 | 正在生成 |
| 完工 / 举手 | 生成成功 |
| 交付 / 点赞 | 复制成功 |

猫可以**按住拖动**到屏幕任意位置，位置会记住（存于 `chrome.storage.local`）。

## 🐱 默认猫 / 替换成你自己的猫（可选）

本项目**默认自带作者本人的小猫修理工动画**，开箱即用。如果你想换成自己的宠物，按下面说明替换即可。

### 你需要准备的材料

| 材料 | 规格要求 |
|---|---|
| **带透明背景的视频素材** | 建议 4 段短视频，分别是：待机、钻钻钻、完工、交付 4 种状态 |
| **帧提取工具** | 本项目要求提取为 **PNG 帧序列**，推荐 [ffmpeg](https://ffmpeg.org/) |
| **背景去背（如需要）** | 如果你的素材是绿幕/黑底/普通背景，需先用工具去背为透明通道（如 [remove.bg](https://www.remove.bg/) 或 Photoshop AI 去背） |

### 帧命名与目录结构

```
assets/frames/
├── idle/        # 待机/热身（73 帧，20fps，ping-pong 往返）
├── drill/       # 生成中：钻钻钻（12 帧，12fps）
├── hand/        # 生成成功：完工/举手（12 帧，12fps）
└── delivery/    # 复制成功：交付（12 帧，12fps）
```

每个目录里的文件名格式统一为：`f_000.png`、`f_001.png` … 从 0 开始，**3 位补零**。

> 透明 PNG 尺寸建议一致（原项目约 320px 宽），背景完全透明（不含任何色块）。

### 抽帧命令示例

```bash
# 待机帧：从透明背景视频抽 73 帧，20fps，宽度 320px，等比缩放
ffmpeg -i your-cat-idle.mov -vf "scale=320:-2,fps=20,format=rgba" -start_number 0 assets/frames/idle/f_%03d.png

# 钻钻钻 / 完工 / 交付：各抽 12 帧，12fps
ffmpeg -i your-cat-drill.mov  -vf "scale=320:-2,fps=12,format=rgba" -start_number 0 assets/frames/drill/f_%03d.png
ffmpeg -i your-cat-hand.mov   -vf "scale=320:-2,fps=12,format=rgba" -start_number 0 assets/frames/hand/f_%03d.png
ffmpeg -i your-cat-delivery.mov -vf "scale=320:-2,fps=12,format=rgba" -start_number 0 assets/frames/delivery/f_%03d.png
```

### 修改帧数配置

如果素材的帧数与默认不同（如把 drill 改成 15 帧），同步修改 `content.js` 顶部的：

```js
// 在 content.js 开头附近，按你的实际帧数修改
const FRAME_COUNT_DRILL = 15;
const FRAME_MS_DRILL = Math.round(1000 / 12); // 或你想要的 fps
```

> 帧数不同但忘记改配置，动画会出现循环跳变或进度错位。

## 🛠️ 开发

```bash
npm test          # 运行全部测试（node:test）
```

- 测试位于 `tests/`，共 6 个文件 / 34 个用例，覆盖：岗位信息提取、模型输出处理（含思考过程拦截与抢救）、连接流程、动画播放器、UI 规范、帧素材校验
- `tests/frame-assets.test.mjs` 需要系统安装 **ffmpeg**（校验帧的透明背景），未安装时可单独跳过
- 无构建步骤：直接编辑源码，浏览器「重新加载」即可

### 项目结构

```
.
├── manifest.json          # MV3 清单（权限 / content script / web_accessible_resources）
├── content.js             # 页面脚本：抓取岗位 DOM、面板 UI、猫动画与拖动
├── background.js          # Service Worker：设置存取、调用 AI API、输出净化
├── popup.html / popup.js  # 工具栏弹窗（配置状态 + 安装指引）
├── options.html / options.js  # 设置页
├── assets/frames/         # 4 组透明 PNG 帧动画
├── docs/                  # 开发过程文档
└── tests/                 # 自动化测试
```

### 关键实现说明

- **岗位抓取**：先按优先级尝试 `TITLE_SELECTORS` / `DESC_SELECTORS`，再按「职位描述/岗位职责/任职要求」标题向上找容器，最后退化为页面最长文本块；同时提取公司名
- **输出净化**：`normalizeContent()` 兼容 `content` 为字符串或内容块数组；`containsReasoningLeak()` 检测思考过程/多版草稿（含「出现 ≥2 次问候语」「18 类草稿特征词计分」等规则）；`extractFinalIntro()` 在泄漏时从中抢救出最后一版成品
- **请求兼容**：遇到 HTTP 400/422（模型不支持 `system` 角色或 `temperature`）时，自动降级为「单条 user 消息 + 精简参数」重试
- **动画**：帧预加载 + `<canvas>` 连续 `drawImage`（避免 `<img>` 换 `src` 的空档透出页面背景），并在首尾帧间往返播放以避免接缝跳变

## ❓ 常见问题

| 现象 | 原因与处理 |
|---|---|
| 报「HTTP 401」 | API Key 错误或未保存，重新填写并保存 |
| 报「域名未授权」 | 保存设置时 Chrome 的权限弹窗需点「允许」；也可到 `chrome://extensions` → 本扩展「详情」→「网站权限」手动添加 |
| 提示「扩展已更新，请刷新页面」 | 扩展重新加载后，旧页面里的脚本已失效，按 `F5` / `Cmd+R` 刷新即可 |
| 提示「请先填写姓名和真实经历素材」 | 到设置页补齐「个人素材」后重试 |
| **输出里混入思考过程** | 说明模型是推理模型。扩展会自动提取最终成品并标注「已自动清理思考过程」；若仍失败，请改用 `deepseek-chat` 这类非推理模型 |
| 岗位描述抓取不完整 | SPA 异步渲染，点「重新抓取页面内容」；或手动补充。若页面文字可选中，拖选复制会更准 |
| 猫动画有卡顿 | 帧素材较大（约 29MB），可降低帧率或尺寸后重新抽帧 |

## 🔒 隐私

- API Key 与个人素材保存在 `chrome.storage.sync`（你的 Chrome 配置内），**不会**发送给本项目作者
- 岗位描述与素材仅发送到**你自己配置的 API 地址**
- 扩展不含任何统计、遥测或远程上报代码
- 唯一在本地记录的是猫的位置（`chrome.storage.local`）
